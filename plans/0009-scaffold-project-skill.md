# Plan: Make "scaffold it from project-template" an executable step, and teach grill-me the greenfield case

## Goal

Both the global `CLAUDE.md` (§ ExecPlans and ADRs) and `grill-me` say "offer to scaffold from `Taka499/project-template`", and nothing executes it. On 2026-09-05 a `/grill-me` session started from `~/Developer` with a product idea and no repository: the skill's first step ("locate the capture homes") had nowhere to route, the interview ran with the Decision Log held in chat, and the scaffold was done by hand at the end — four files copied, two failed sandboxed `git init` attempts, `CLAUDE.md` filled, first commit proposed. That sequence will recur every time an idea precedes its repo. After this change it is a skill, and `grill-me` knows what to do when the repo does not exist yet.

## Changes

- `skills/scaffold-project/SKILL.md` — new. Settles name, parent directory, and a separate "create it and initialise git now?" with the user before creating anything; after an unsandboxed fetch and `remote set-head origin --auto`, archives `origin/HEAD` to a file and extracts it into a freshly `mkdir`ed target, rather than copying a checkout or a hardcoded list; runs `git -C <target> init -b main` outside the sandbox with the observed failure recorded as an observation; fills the `CLAUDE.md` overview and ADR index from what the session knows and leaves the code-dependent sections as template comments; proposes but never runs the first commit.
- `skills/grill-me/SKILL.md` — "Locate the capture homes first" now names `scaffold-project` for the missing-scaffold case and gains a greenfield paragraph: run the interview first; close with three one-at-a-time questions (create a repo now at all, its name, its location); number decisions in chat, and in a `$TMPDIR` scratch file if the interview is long, so the final transfer is a copy.
- `CLAUDE.md` — one bullet under § Skills pointing at `scaffold-project` (no slash: it is model-invocable, and the list uses the slash form only for user-invoked skills); § ExecPlans and ADRs names the skill where it already said "offer to add it from project-template", scoped to a repository that does not exist yet.
- `README.md` — `scaffold-project` added to the list of model-invocable skills in the layout section.

## Decision Log (session 2026-09-07)

- **Extract `git archive` of the remote tip, not a fixed list and not the checkout** — the template will grow (it already gained `.gitkeep` in its last commit), and a skill carrying its own list would ship a stale scaffold without anyone noticing until a plan failed to find `docs/PLANS.md`. The first draft enumerated `git ls-files` and copied from the working tree; the Codex review (below) pointed out that this reads dirty edits and fails on a deleted tracked file, and that a stale or wrong branch was only warned about. Archiving `origin/HEAD` after a fetch and `remote set-head origin --auto` makes the local checkout's state irrelevant and never guesses the default branch; the target is created with a plain `mkdir` first so an existing path fails rather than merges. The archive is the revision's export contents, which equals the tracked files while the template has no `export-ignore` attributes. Verified on the real template: the archive extracts the four tracked files including `docs/plans/.gitkeep`.
- **`git init` runs unsandboxed, and the skill records the observation without a cause** — two sandboxed attempts failed: copying Xcode's sample hooks into `.git/hooks`, then writing `.git/config` after `--template=` had dodged the hooks. Plain `cp` and `python3` writes into the same new directory succeeded in the same session. The first draft explained this as "the sandbox's writable `.` is the launch directory and the new directory is a sibling"; the Codex review objected that neither `README.md` nor `plans/0006` establishes launch-directory containment, and the successful copies contradict it. Accepted: the skill now states what was observed and that the cause was not established. Recording the evidence still stops the next session from re-deriving it or "fixing" it with a permission rule.
- **Repository questions come last, one at a time, and "create it?" is its own question** — in the session, name and home were asked last by accident (the skill assumed a repo) and it worked well: the design had a shape, so the name had something to name. The first draft folded name and location into one "closing question" and let `grill-me` proceed to scaffold once both were known; the Codex review rated this HIGH: agreeing on a name is not a request to create a directory, so `/grill-me` alone could have led to unrequested filesystem creation, against the global "only requested changes" rule, and the paired question strained grill-me's one-question-at-a-time rule. Accepted: three questions, and the skill re-asks the create question against the full path.
- **Name candidates in more than one register** — the first candidate set was all short Japanese words, matching the neighbouring directories, and the user rejected all of them and asked for English. A neighbourhood is not a preference; the skill offers both and lets the user pick.
- **Model invocation stays enabled** — unlike `grill-me`, this skill cannot start an open-ended process on its own inference: it asks a separate yes/no against the full path before creating anything and never commits. That explicit create question, not mere path agreement, is what makes automatic invocation safe, so it is stated as the skill's first section.
- **A failed template fetch is fatal, and runs unsandboxed for SSH remotes** — found by the verification probe, not by review: a refused fetch leaves `origin/HEAD` stale, and `git archive` of a stale ref produces an old scaffold with no error. Warning and continuing, as the first draft did, is the worst option because the output looks correct.
- **The skill creates repositories; it does not retrofit an existing one** — the existing-repo case (a project with code but no `docs/PLANS.md`) is real but different: no name, no `git init`, no create confirmation, and a merge into files someone already wrote. Folding it in would give the skill two modes with opposite safety rules. The pointers say which case the skill covers, and the other stays a described manual step until it recurs enough to earn its own skill.
- **No ADR** — the change is a skill and two paragraphs, all trivially reversible. Fails gate one.
- **Codex review, 2026-09-08** — run per `/codex-review` on the branch diff; verdict `CODEX VERDICT: CHANGES REQUESTED`, seven findings (one HIGH, three MED, three LOW). All seven were verified against the files and accepted; the three substantive ones are recorded in the entries above, the rest were wording (the plan said `/scaffold-project` with a slash; "exactly these steps" overstated the hand-run precedent; README's safety claim rested on path agreement). Nothing was rejected. A second pass on the revised diff confirmed the HIGH finding closed and raised two MED gaps, both accepted: the target directory was never created before `tar -x`, and an unset `origin/HEAD` fell back to a guess; plus wording (`git archive` honours `export-ignore`; a failed clone should stop like a failed fetch). A third pass found a HIGH literal-execution hazard, accepted: step 3 said `git init -b main` with no target, which an agent could run in the session's current repository; it is now `git -C <target> init -b main`. It also found that the `CLAUDE.md` and `grill-me` pointers claimed the skill adds a missing scaffold to an *existing* repository while the skill refuses existing paths; resolved by scoping the pointers to new repositories and describing the existing-repo case as a manual copy of the missing files from the same archive, rather than widening the skill. And a LOW: `git archive | tar` masks an archive failure, so the archive now goes to a file first. A fourth pass confirmed the HIGH closed and asked that the create question also name `git init`, since the global Git rule wants explicit permission per operation; accepted, along with refreshing this plan's Changes bullet to the shipped commands. One gap Codex did not raise, added on the first pass: a long greenfield interview can have its context compacted, so the numbered in-chat Decision Log now also goes to a `$TMPDIR` scratch file.

## Verification

Its first commit lists the four template files plus the ADRs and plan, which is the file list the skill's step 6 produces.
- `git -C ~/Developer/project-template archive origin/HEAD | tar -x -C "$TMPDIR/archive-probe"` extracts exactly `CLAUDE.md`, `docs/PLANS.md`, `docs/adr/README.md`, `docs/plans/.gitkeep` — after an unsandboxed fetch. The first, sandboxed run of the same probe is the evidence for the fetch rule: the fetch was refused by the sandbox proxy (SSH remote), `origin/main` was one merge behind (`f1278f0` vs `b52b8df`), and the archive extracted `docs/plans/.gitignore`, the file the template's latest commit had replaced. The local checkout was also on a feature branch at the time, which is why copying its working tree on 2026-09-05 gave the right files only by luck.
